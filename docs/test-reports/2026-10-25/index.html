여러 키오스크가 동시에 써도 1초 안에 맞춰지는가

개선한 키오스크(Faith ID)와 DB 서버(Faith DB Server)를 단위·통합·기기 단계로 시험했습니다. 키오스크 여러 대가 순서 없이 내려받고 변경을 보내는 상황에서, 변경이 서버와 다른 키오스크에 닿는 시간과 서버 응답 시간을 측정했고, 측정에서 찾은 서버 지연을 고친 뒤 다시 측정했습니다.

8대 동시 수신은 태블릿 Wi-Fi 대역폭(합계 약 37 MB/s)이 상한입니다. 1,000명 규모에서 주일 아침 키오스크 여러 대를 한꺼번에 켜도 10초 안에 준비됩니다.

의도된 대기. 키오스크는 카메라 앞에 사람이 있는 동안 받은 변경을 적용하지 않고 최대 30초 기다립니다(인식 중에 DB가 바뀌지 않도록). 측정 중 태블릿 앞에 사람이 있었던 회차에서는 전체 수신이 39초 걸렸고, 이 값은 표에서 뺐습니다. 출석 전송은 이 대기와 상관없이 바로 나가도록 이번에 고쳤습니다(#14).

4다중 키오스크 통합 시험

키오스크마다 독립된 DB와 네트워크를 두고, 각자 무작위 순서로 등록·샘플 추가·출석을 하면서 동시에 내려받게 했습니다. 네트워크 장애는 일부러 넣었고, 관리자도 동시에 수정·삭제·승인 해제·서버 재시작을 했습니다. 끝나면 모든 키오스크와 서버의 DB를 사람·샘플 단위로 비교합니다.

9한계와 다음 일

  • 실제 얼굴은 1명. 닮은 사람, 안경·마스크, 어린이, 역광에서의 오인식과 미인식 비율은 아직 모릅니다. 실제 교인 데이터로 판정 기준(0.40 / 0.10)을 다시 정해야 합니다.
  • 키오스크는 PC에서 모의. 동시 키오스크 8대는 PC 프로세스였고 실제 태블릿 키오스크는 1대였습니다. 서버 쪽 동작과 Wi-Fi 경로는 실제와 같지만, 키오스크 기기의 저장 속도는 실제 키오스크 앱 측정(반영 181 ms, 전체 수신 약 4.2초)으로만 확인했습니다.
  • 규모. 1,000명, 초당 6.7건 변경까지 확인했습니다. 실제 주일 출석 몰림은 이보다 훨씬 적을 것으로 보지만, 실제 현장 수치로 확인한 것은 아닙니다.
  • 인쇄. 프린터 연결은 이번 시험 범위가 아닙니다. 출석은 인쇄 결과와 무관하게 기록되는 것을 확인했습니다.
